## Blocker

### QA-001 · onboarding · Setup fails on both paths, so no company can be created and the whole product stays empty
- **URL:** https://openfront-construction-production.up.railway.app/dashboard/platform/setup
- **Steps:**
  1. Sign in as the new admin and open Setup.
  2. **Your company:** fill every field, for example company "QA Ridgeline Builders", slug `qa-ridgeline-builders`, brand mark `QR`, email `qa.ridgeline@example.test`, project `QA-2026-001`, cost code `03-3000`, budget code `03-3000-LAB`. Click **Create workspace**.
  3. Repeat with only the required fields.
  4. Switch to **Sample workspace** and click **Load sample workspace**.
- **Expected:** "Workspace ready", a company and first project, and a published storefront.
- **Actual:**
  - Every attempt ends after about 10 s with "Unable to complete the request. Please try again." on both `f1e55c8` and `3940476`.
  - Afterwards, `companiesCount` is 0, the user has no `CompanyMembership`, and the storefront still says "This website is not published yet".
  - With no company:
    - Portfolio, Projects, Trade partners, Cost codes and Equipment & materials show "No company yet".
    - Store Settings shows "No company you can manage".
    - The project workspace can't be reached.
  - A new contractor cannot get past day one.
- **Cause (not confirmed, no logs):** production masks the real error (QA-003), and I did not run Railway commands.
  - The Railway logs for `onboardConstructionWorkspace` (about 21:50–22:10 CDT on 2026-10-23) will show the thrown error.
  - Both paths share the transaction in `features/keystone/mutations/onboarding.ts` (`onboardConstructionWorkspace` → `seedWorkspaceSetup` / `seedSampleWorkspace` → `assertWorkspaceReady` in `features/keystone/domain/onboarding-seed.ts`). The failure is therefore in that shared path, not in either form.
  - A strong lead is QA-002: the three evidence lists that onboarding writes (AgentAction, IdempotencyKey, OutboxMessage) throw a Keystone input error for this admin on any non-sudo read. If any hook or nested `query:` in the transaction reads them through the user's context, it would throw the same way.
- **Likely files:** `features/keystone/mutations/onboarding.ts`, `features/keystone/domain/onboarding-seed.ts`, and `features/keystone/access.ts:258-274`.

## Major

### QA-002 · dashboard · Agent Actions, Idempotency Keys and Outbox Messages fail to load for the platform admin, and that blanks every count on the dashboard home
- **URLs:** /dashboard/agent-actions, /dashboard/idempotency-keys, /dashboard/outbox-messages, /dashboard
- **Steps:** Signed in as the admin, open any of the three lists, then open the Dashboard home.
- **Expected:** The lists load (they are empty), and the home shows a count on each of the 86 model cards.
- **Actual:**
  - Each list shows "Failed to load items: Unable to complete the request. Please try again."
  - Over GraphQL, `agentActionsCount`, `idempotencyKeysCount` and `outboxMessagesCount` all return `Input error: Only a string can be passed to id filters` (`KS_USER_INPUT_ERROR`).
  - Other counts work (`usersCount: 1`, `companiesCount: 0`).
  - The Dashboard home asks for all 86 counts in one query (`features/dashboard/actions/getListCounts.ts`), so these three errors make **every** card read "Unknown", including Users.
- **Cause:** all three lists use `projectEvidencePermissionFilter` (`features/keystone/access.ts:258`). Its company branch adds `{ NOT: { project: { id: { not: { equals: "" } } } } }` (line 271). Keystone's ID filter rejects the nested `not: { equals }` object with exactly this error. The code comment says the form was picked to avoid `id.equals: null`, but production rejects it. Use the relationship's own null check (`{ project: null }`) instead.
- This may also be the cause of QA-001.

### QA-003 · dashboard / onboarding · Every server error reaches the merchant as "Unable to complete the request. Please try again."
- **URL:** /dashboard/platform/setup (and any platform form)
- **Steps:**
  1. Submit onboarding (QA-001).
  2. Separately, call `onboardConstructionWorkspace` with an obviously invalid input (email `bad`, summaries `x`).
- **Expected:** The specific validation message, for example "Public contact email is invalid", "Planned completion must be after the start date" or "Company slug is invalid". `onboarding.ts:153-214` already throws these.
- **Actual:**
  - GraphQL returns `"Unexpected error."` even for that plain validation failure.
  - The server action then shows `PUBLIC_REQUEST_ERROR` ("Unable to complete the request. Please try again.", from `features/dashboard/lib/security.ts:2`).
  - The merchant can't tell a typo from an outage, and "try again" sends them into the same failure.
- **Likely files:** the GraphQL `formatError` / masking in the Keystone config, `features/dashboard/lib/keystoneClient`, and `features/platform/onboarding/actions/onboarding.ts:113`. Pass the messages of deliberate domain errors through, and keep masking only unexpected ones.

### QA-004 · onboarding · A failed Setup submit wipes all 30 fields
- **URL:** /dashboard/platform/setup
- **Steps:** Fill the whole "Your company" form, including the summaries and the published-project section, and click **Create workspace**.
- **Expected:** The error appears next to the filled form.
- **Actual:**
  - Every field returns to blank or its placeholder.
  - The "Publish a curated public project entry" box is unticked.
  - Only the default privacy notice remains.
  - The merchant has to retype company, profile, project and budget details after every error.
- **Cause:** `OnboardingForm.tsx` passes the server action to `<form action={action}>`. React 19 resets uncontrolled forms after a form action. Real Estate fixed the same thing by submitting through `startTransition` (or by passing values back in the state).
- **Same pattern elsewhere:** `TradePartnerForm.tsx`, the cost code, catalog and structure forms, and `DemoFixtureForm.tsx` use the same `action={action}` pattern. On a server refusal (for example "QA Lone Star Concrete is already in the directory" or "03-3000 already exists") they will clear what was typed. That is from reading the code; it could not be exercised live without a company.
